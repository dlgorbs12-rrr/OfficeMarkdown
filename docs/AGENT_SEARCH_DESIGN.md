# 문서·그림 검색 에이전트 구현 설계안

**목표**는 5만 건 이상인 보관함에서 사용자가 기억하는 고객사명, 업무 내용, 화면 특징으로 원하는 문서와 정확한 위치를 찾는 것이다. 기존 Swing 화면, SQLite FTS5, 에이전트 CLI 연결을 사용한다. 핵심 변경은 구역·그림 단위의 후보 조회, OCR과 별도로 저장하는 그림 설명, 선택한 대상을 기억하는 검색 하네스다.

## 1. 현재 구현에서 바꿀 지점

| 확인한 동작 | 설계 결정 | 이유 |
| --- | --- | --- |
| 에이전트는 검색어를 단어로 나눠 OR 검색 상위 120건에서 최대 24개 문서를 고른다. Markdown을 다시 읽고 발췌문 최대 8개를 전달한다. | 문서명, 구역 내 구절, 그림의 특징을 구분해 해당 단위에서 후보를 조회한다. | 흔한 단어의 결과가 초기 한도를 채우면 에이전트는 정답을 볼 수 없다. |
| 검색 호출은 보관함 동기화 후 조회한다. 캐시 전용 조회 경로도 있다. | 하네스의 반복 조회는 저장된 색인을 읽는다. 변환 완료·백그라운드 갱신·새로고침은 기존 색인 경로가 담당한다. | 한 질문에서 여러 번 조회해도 전체 보관함 점검은 한 번 더 할 필요가 없다. |
| 그림 검색에는 OCR 문자열이 색인된다. 에이전트 답변은 최종 근거를 만들면서 그림 참조를 잃는다. | 그림 설명과 OCR을 별도 필드로 검색하고 최종 결과에 그림 참조를 유지한다. | 이미지 검색의 정답은 그림이 들어 있는 문서뿐 아니라 해당 그림의 등장 위치다. |

광범위한 태그는 결과를 좁히는 용도로 사용한다. 벡터 검색 도입 여부는 텍스트 설명을 색인한 뒤에도 표현 차이로 정답 후보가 누락되는 질의가 얼마나 남는지 측정해 결정한다.

## 2. 사용자가 보게 될 결과

| 질의 | 사용할 단서와 범위 | 기대 결과 |
| --- | --- | --- |
| “고객사 C 제안서에서 SSO 연동 구성도 찾아줘” | 문서명의 고객사 C, 같은 슬라이드 본문의 ‘목표 시스템 구성도’와 ‘SSO 인증 연동’ | 24쪽 카드, 일치 문구, MD 위치 보기와 원본 열기 |
| “그 장표의 계정 복구 로그인 화면 보여줘” | 선택한 24쪽의 그림만 조회. 그림 자체의 ‘로그인’, ‘계정복구’ OCR과 화면 설명을 대조 | 해당 변환본의 그림 203 썸네일과 그림 열기 |
| “다른 제안서에도 이런 화면이 있어?” | 선택한 그림 유형·특징으로 조회하고 현재 문서를 제외 | 문서별 대표 썸네일과 유사하다고 판단한 근거 |
| “IAM” | 구체적인 단서가 하나뿐 | 문서별 대표 결과와 문서·구역·그림으로 좁힐 선택지 |

24쪽 전체는 도형과 텍스트가 결합된 장표다. 슬라이드 전체를 렌더링하거나 그 안의 모든 아이콘에 ‘SSO’를 붙일 필요 없이 구역 본문으로 찾을 수 있다. 그림 203이라는 번호는 해당 변환본 안에서만 유효하다.

## 3. 그림 설명의 생성·보존

**생성 계약.** 저장된 그림 픽셀을 받아 유형 하나(화면, 로고, 표, 도식, 아이콘, 기타), 관찰 가능한 특징을 담은 한국어 한 문장, 판독 가능 여부를 반환한다. 예를 들어 “QR코드 오른쪽에 남은 시간이 표시된 화면”이다. 원본 작성자의 대체 텍스트, OCR 원문, 생성 설명을 구별해 저장한다. 특징을 알기 어려운 그림에는 업무명이나 제품명을 추정해서 붙이지 않는다. OCR이 비어 있는 그림도 대상이다.

**중복 처리.** 보관함 안에서 원본 그림 바이트의 SHA-256과 생성 프로필 버전을 합쳐 설명의 유일 키로 사용한다. 프로필은 모델·프롬프트·전처리 버전을 포함한다. 설명 입력은 그림 자체로 제한하고 슬라이드 제목과 주변 문구는 검색 시 등장 위치에 연결한다. 그래야 다른 문서에서 같은 그림을 썼을 때 앞 문서의 설명이 섞이지 않는다.

**저장 위치.** 보관함에 별도 영속 SQLite 파일을 둬 생성 결과와 작업 상태를 보존한다. 검색 DB를 다시 만들 때 이 파일에서 설명을 복구한다. 첫 버전은 앱의 그림 상세 화면에서 OCR 아래에 설명을 표시한다. 기존 Markdown 파일 안에 설명을 써 넣는 방식은 보류한다. 현행 OCR 복구가 그림 링크·캡션·OCR 블록의 순서를 검증하면서 문서와 그림 자산 세대를 함께 교체하기 때문이다.

**실행과 복구.** 문서 또는 폴더 범위를 골라 저장된 자산을 백그라운드에서 처리한다. 대기·처리 중·완료·재시도 가능 오류·처리 불가를 구분한다. 작업 점유에는 만료 시간을 두고 중단 후 재개한다. 완료 결과와 색인 반영 요청을 같은 트랜잭션으로 저장하고, 색인 반영을 반복해도 같은 결과가 되도록 한다. 원격 요청 직후 중단된 작업은 재호출 비용이 발생할 수 있어 시도 횟수를 기록한다.

**모델 선택.** 검색용 텍스트 에이전트와 설명용 비전 모델 설정을 분리한다. 기존 MarkItDown 비전 워커는 문자 추출용이므로 그림 설명에는 별도 출력 계약이 필요하다. 외부 모델 사용 시 선택 범위, 고유 그림 수, 목적지와 모델을 실행 전에 표시한다. 검색 때는 상위 후보의 텍스트 근거만 에이전트에 전달한다.

## 4. 검색 데이터와 식별자

| 단위 | 참조 | 색인하거나 표시할 내용 |
| --- | --- | --- |
| 문서 | 보관함 + 변환본 상대 경로 | 문서명과 원본 위치. 재색인하면 바뀔 수 있는 DB 행 번호를 대화 상태에 저장하지 않는다. |
| 구역 | 문서 참조 + 변환본 버전 + 구역 순번 | 구역 이름, 직접 얻을 수 있는 제목, 본문과 위치. PPT는 슬라이드, PDF는 페이지, Word는 구역, Excel은 시트와 행 범위로 표시한다. |
| 그림 등장 위치 | 문서 참조 + 자산 세대 + 매니페스트 파일명 | 구역 참조, 그림 위치, 자산 해시, OCR 원문, 작성자 설명, 생성 설명 참조 |
| 일치 근거 | 요청 안에서 발급한 후보 ID + 필드 + 일치 문구 | 문서명·구역 본문·그림 OCR·작성자 설명·AI 설명 중 실제로 맞은 출처와 열기 대상 |

구역 색인은 Markdown을 순차적으로 읽어 만든다. 큰 시트나 구역은 작은 본문 조각으로 색인하고 결과는 구역별로 묶는다. 같은 이름의 구역은 순번으로 구분한다. 24쪽의 구역 이름은 ‘슬라이드 24’이고 ‘목표 시스템 구성도’는 본문에 있다. 문서 첫 줄을 모든 자료의 제목으로 간주하지 않는다. 그림과 직접 연결할 수 없는 기존 대체 텍스트도 구역 근거로만 사용한다.

구역·그림 검색용 FTS 필드를 추가하되 기존 일반 검색과 그림 OCR 복구는 기존의 원문 필드를 사용한다. 그림의 자체 근거와 소속 페이지의 문맥은 조회 결과에서도 구별한다.

## 5. 검색 하네스와 결과 화면

모델은 질문을 구조화하고 후보를 선택한다. 앱은 허용된 검색 도구를 실행하고, 현재 범위와 결과 ID를 검증하며, 다음 상태로 이동한다. 기존 CLI의 도구 비활성화 방식에서도 이 구조를 사용할 수 있다.

| 도구 | 입력 | 응답 |
| --- | --- | --- |
| 문서·구역 검색 | 찾을 단위, 문서명 단서, 원문 구절, 포함·제외 문서, 한도 | 문서·구역 후보와 참조, 실제로 일치한 필드와 문구 |
| 그림 검색 | 포함·제외 문서 또는 구역, 화면 유형·특징, OCR 구절 | 그림 등장 위치, 썸네일 참조, OCR·설명·문맥별 근거 |
| 후보 확인 | 이번 요청에서 발급된 후보 ID, 필요한 문맥 범위 | 해당 구역 발췌 또는 그림의 OCR·설명과 위치 |

1. **범위 결정.** 찾기·보여주기·근거로 답하기를 구분하고 문서명, 원문 구절, 시각적 특징을 추출한다. 사용자가 지정한 범위와 모델이 추정한 단서를 구분한다. “그 장표”는 선택한 구역을 우선하고 직전 후보가 하나면 그 후보를 사용한다. 후보가 여럿이고 선택이 없으면 화면에서 고르게 한다.
2. **후보 조회.** 구절을 보존하고 띄어쓰기 차이는 별도 정규화 필드에서 처리한다. ‘계정 복구’가 ‘계정복구’와 일치해도 화면에는 실제 원문을 표시한다. 선택 문서·페이지 조건은 먼저 적용한다. 조회마다 보관함 파일을 다시 열지 않는다.
3. **순위 결정.** 정확 구절, 보관함 문서 빈도가 낮은 식별어, 같은 페이지나 같은 그림에 모인 단서에 가중치를 준다. 동의어는 보조 단서다. OCR과 설명에 같은 단어가 반복된 경우 단순 중복 가산하지 않는다. 같은 로고의 여러 등장은 대표 썸네일과 위치 목록으로 묶는다.
4. **필요한 경우 재검색.** 명시한 단서를 충족하는 후보가 없을 때 한 번만 구절 분리·표기 변형으로 다시 찾는다. 문서·페이지 제한은 유지한다. 시작 예산은 조회당 후보 최대 50개, 모델에 전달하는 근거 최대 8개다. 텍스트 검색만으로 맞는 대상이 명확하면 결과 카드를 즉시 표시하고 추가 모델 호출을 생략한다.
5. **검증과 표시.** 후보 ID, 현재 보관함과 자산 세대, 인용문이 출처 필드에 존재하는지 앱이 확인한다. ‘찾아줘’에는 결과 카드, ‘보여줘’에는 썸네일, ‘설명해줘’에는 인용 답변을 우선한다. 원본 파일 열기와 정확한 MD 위치 이동은 별도 동작이다. 모델이 실패해도 이미 확보한 로컬 결과는 표시하고, 처음부터 모델을 사용할 수 없으면 입력 문구로 검색한다.

대화 상태는 창 단위로 앱이 보관한다. 보관함을 바꾸면 선택을 초기화하고, 질문 취소 또는 새 질문 후 늦게 도착한 응답은 무시한다. 문서에서 읽은 텍스트와 생성 설명은 검색 자료로만 전달하고 도구의 입력 범위·파일 위치·후보 ID는 앱이 결정한다.

## 6. 기존 보관함과 대규모 운영

- 검색 스키마 버전과 문서별 색인 버전을 기록한다. 새 색인이 없는 문서는 파일 시각이 같아도 순차 보강하고, 재시작 시 체크포인트에서 이어간다. 문서별 구역과 그림 색인을 한 트랜잭션으로 교체한다. 보강 완료된 문서는 새 경로, 대기 문서는 기존 검색 경로를 사용하고 결과는 문서 참조로 합친다. 최초 색인 중이면 현재 검색 가능한 범위를 표시한다.
- 변환 완료나 외부 변경 시 영향을 받은 문서를 갱신한다. 색인 대용량 보류 설정을 새 조회에도 적용한다. 보관함 전체 파일의 해시 계산을 매번 검색 경로에 넣지 않는다.
- 기존 trigram 경로는 세 글자 미만의 단어에서 스캔 비용이 커질 수 있다. 짧은 한글 단어의 정확 일치용 보조 인덱스를 두고, 복합 질의에서는 먼저 좁혀진 후보에서 부분 문자열을 검증한다. 기존 일반 검색의 부분 일치 의미는 유지한다.
- OCR 복구도 자산 세대를 바꿀 수 있다. 반영 직전 세대와 변환본 버전을 확인하고 바뀌었으면 현재 자료를 다시 읽는다. 그림 바이트가 같으면 설명을 재사용한다. 예전 그림 참조가 여러 새 등장 위치와 맞으면 재선택하게 한다. 동시 삭제된 문서가 늦게 끝난 설명 작업으로 검색에 다시 나타나지 않도록 현재 등장 위치에만 연결한다.

## 7. 구현 순서와 인수 기준

| 단계 | 구현 범위 | 검증 기준 |
| --- | --- | --- |
| 1. 검색 기준선과 참조 | 현행 검색 결과 기록, 구역·그림 참조와 위치, 필드별 근거 조회 | 실제 제안서에서 ‘목표 시스템 구성도’로 24쪽, ‘계정복구’로 해당 그림을 연다. |
| 2. 그림 설명 보강 | 설명 워커·영속 저장·기존 자산 배치·증분 색인 | 모델 미설정 상태의 OCR 검색, 중복 그림 1회 처리, 중단·재개, OCR 복구 후 재연결, 검색 DB 재생성을 검증한다. |
| 3. 하네스와 화면 | 세 도구, 재검색 상한, 결과 카드, 후속 질문, 취소 | 24쪽 → 그 장표의 로그인 화면 → 다른 문서의 유사 화면 흐름을 검증한다. 잘못된 후보 ID와 출처가 다른 인용을 거른다. |
| 4. 규모 검증 | 실제 분포를 반영한 5만 건 이상 보관함, 현행 대비 성능·품질 비교 | 로컬 검색과 외부 모델 지연을 분리해 측정하고 순위·예산을 조정한다. |

**평가 자료.** 여러 문서에서 고객사명, 비슷한 제안서 버전, 작은 로고, OCR이 빈 그림, 글자 없는 아이콘, 검색 결과가 없어야 하는 질문, 후속 질문을 선정한다. 정답은 문서·구역·그림 위치까지 기록한다. 순위 조정과 최종 평가에는 서로 다른 질의를 사용한다.

**품질 지표.** 현행 → 구역·그림별 OCR 검색 → 설명 추가 → 하네스 추가를 같은 질의로 비교한다. 후보 50개 내 정답 포함률, 문서·구역 상위 5개 적중률, 그림 상위 3개 적중률을 따로 집계한다. 문서는 맞아도 그림이 다르면 그림 찾기 실패다. 후속 질문의 참조 오류와 근거 없는 답변도 집계한다.

**운영 지표.** 문서·구역·그림·고유 그림 수와 디스크 사용량, 최초·증분 색인 시간, 캐시 준비 전후 로컬 조회 p50/p95, 첫 결과 카드까지의 시간, 모델 호출 횟수·비용을 기록한다. 기존 7만 건 시험은 합성 제목 조회 결과이므로 이 기능의 처리량으로 환산하지 않는다. 출시 전에는 기존 정확 구절 검색의 회귀와 잘못 열리는 링크를 점검하고, 그림 설명이 필요한 질의에서 개선 여부를 확인한다.

**남은 운영 결정.** 설명 모델과 처리 위치, 첫 보강 대상 문서, 외부 처리 비용과 허용 지연은 파일럿에서 확정한다. 정밀 OCR과 실제 24쪽 자료로 단계 1을 시작할 수 있다. 모델 준비 전에는 수기로 작성한 설명을 시험 자료로 명시해 검색 흐름을 검증하고, 자동 설명 품질은 실제 모델로 따로 평가한다.
