# 문서 검색 MCP 비교 시험

2026-11-21 로컬 앱에서 Codex CLI가 SQLite 색인을 검색하고 목차와 본문·그림 OCR을 읽도록 연결했다. 이 비교 시험은 Codex로 수행했다. 현재 앱은 세 제공자 모두 ‘MCP 문서 검색’을 제공한다. [클라이언트별 연결 안내](MCP_CLIENTS.md) 에이전트가 호출한 도구가 반환한 근거 ID와 인용 문자열을 앱에서 대조한 뒤 추천 이유, 참고할 부분, 인용 위치를 표시한다. 보관함의 색인은 로컬에 있고, 질문과 선택된 검색 결과·발췌문은 연결된 모델에 전달된다.

## 시험 결과

기존 페이지·구역 검색과 MCP에 같은 질문, 같은 Codex CLI 기본 모델(gpt-6.2-sol), 같은 추론 설정(low)을 적용했다. 문서가 있는 경우 상위 3건과 첫 결과를 확인하고, 없는 경우 빈 결과를 기대했다. 기존 경로의 시간에는 모델의 검색어 추출과 로컬 검색이 포함된다. 각 조건을 한 번 측정했고 여러 질문을 동시에 실행했다.

| --- | --- | --- | --- | ---: |

양쪽 모두 정답 문서 1순위 및 상위 3건 적중 4/4, 정답이 없는 질문에서 잘못된 추천 0/1이었다. 첫 결과의 인용이 표시된 발췌문 안에 있는 경우는 기존 3/4, MCP 4/4였다. 인용 일치는 추천 설명 전체의 정확성을 측정하지 않는다. 상위 3건에 포함된 추가 사례가 PM 실무에 얼마나 유용한지는 별도의 사용자 평가가 필요하다.

첫 MCP 시험에서 AD 설계서 요청에 InterDB 설계서를 추가로 추천했고, 착수보고서는 표지를 인용했다. 명시된 고객·대상 시스템을 필수 조건으로 유지하고 실제 작성 항목이 있는 본문을 우선하게 보정했다. 위 표는 보정 후 결과다. 추가 그림 시험에서는 고객사 C 제안서의 ‘계정복구’ 구성도를 찾아 슬라이드 24를 반환했다(18.0초, 4회). GUI에서도 사전조사서 추천 카드의 이유가 표시되고 ‘미리보기’가 해당 시트를 선택하는지 확인했다.

## 재현

프로젝트 루트에서 로컬 빌드를 마치고 기존 색인이 있는 보관함을 선택한다. 기본 보관함을 대상으로 두 경로를 비교하는 PowerShell 예시다.

```powershell
$appJars = Join-Path (Get-Location) ('local/apps/' + (Get-Content local/current.txt) + '/OfficeMarkdown/app/*')
& "$env:JAVA_HOME/bin/javac.exe" -encoding UTF-8 -cp $appJars -d $env:TEMP qa/McpComparison.java
$library = Join-Path $env:LOCALAPPDATA 'OfficeMarkdown/Markdown'
$query = '지금 사전조사서 문서를 만들건데 iam/sso야 참고할만한 문서'
foreach ($route in 'legacy','mcp') {
    & "$env:JAVA_HOME/bin/java.exe" -cp "$appJars;$env:TEMP" McpComparison $library $route $query
}
```

## 적용 판단

직접 실험으로 확인한 이점은 작성에 참고할 시트·슬라이드 선택과 근거 미리보기다. 5개 질문의 응답 시간 중앙값은 기존 5.6초, MCP 25.5초였다. 일반 검색은 기존 방식을 기본으로 유지하고, 구체적인 참고자료가 필요한 사용자가 MCP 검색을 선택할 수 있게 했다. 5만 건 보관함에서의 성능은 측정하지 않았다. 다음 검증에서는 정답이 없는 질문의 재검색 횟수와, 파일명이 비슷한 여러 고객사 문서가 섞인 조건에서의 상위 3건 적합률을 우선 측정한다.
