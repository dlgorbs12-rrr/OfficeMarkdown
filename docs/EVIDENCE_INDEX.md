# 원본 관계 근거 색인

XLSX와 PPTX를 변환할 때 같은 원본 바이트에서 본문과 SHA-256을 구한다. 변환 폴더의 임시 스냅샷으로 읽고 게시 직전에 원본 지문을 다시 검사한다. 원본이 바뀌면 임시 결과를 버리고 한 번 재시도한다. 임시 사본은 정상 종료와 처리 예외에서 정리한다. 작업 중에는 원본 크기만큼의 임시 공간이 필요하다.

변환 세대는 기존 그림 세대와 함께 바뀐다. 본문 색인이 새 세대를 등록할 때 같은 트랜잭션에서 관계 상태를 PENDING으로 초기화한다. 원본 지문이 없는 예전 Markdown은 일반 검색이 가능하며, 원본을 다시 변환하면 관계 추출 대상으로 등록된다.

## 쓰기와 조회 계약

- 형식별 추출기는 EvidenceIndex.extract에 Markdown 경로, 추출기 버전, 스냅샷을 읽는 함수를 전달한다. 관계는 종류·출발 식별자·도착 식별자·각각의 원본 위치를 가진다. 한 문서에 여러 관계 종류를 쓰면 그 버전이 담당하는 전체 목록을 한 번에 게시한다. 빈 목록의 성공과 추출 실패를 구분한다.
- 추출은 SQLite 쓰기 트랜잭션 밖에서 실행한다. 게시할 때 원래 문서 세대·지문·이전 추출기 버전·대용량 보류 상태를 대조하고, 기존 관계 삭제와 새 목록 삽입을 한 트랜잭션으로 처리한다. 원본 지문과 Markdown 세대가 일치할 때 커밋한다. 쓰기 중 실패하면 이전에 완성한 결과가 유지된다. 임시 스냅샷과 원본 지문을 검사하는 동안 별도 디스크 I/O가 발생한다.
- 저장 인용은 Markdown 위치, 원본 위치, 원본 SHA-256, 변환 세대, 추출기 버전을 사용한다. SQLite의 문서 번호는 내부 외래 키다. read(Version)은 이전 인용을 새 문서의 같은 좌표로 자동 이동시키지 않는다.
- 단일 문서는 read로, 사용자가 한 프로젝트로 선택한 문서 집합은 readSelection으로 조회한다. 결과를 문서별로 반환한다. 각 결과는 해당 문서를 읽은 시점의 버전을 담는다. 프로젝트 선택의 UI·저장과 문서 간 일치 판정은 후속 작업에서 이 계약을 사용한다.
- READY만 관계를 반환한다. PENDING은 등록 후 추출 전, UNVERSIONED는 지문이 없는 색인, STALE은 원본·변환·추출기 버전 불일치, MISSING은 파일 소실, NOT_VISIBLE은 색인에 없거나 보류 중인 문서다. 지원하지 않는 형식에서도 지문 없는 본문의 기존 검색이 가능하다.

## 성능과 정확도 검증

#2의 가상 원본 7개를 같은 경로에 놓고 변경 전후 각 5회, 매번 새 JVM·새 색인으로 비교했다. Windows x64, i9-12900K, JDK 21 환경이다. 실행 순서를 교대로 바꾸고 조회 p95는 버전별 95개 조회에서 계산했다.

| 지표 | 변경 전 | 변경 후 | 소형 자료 예산 |
|---|---:|---:|---:|
| 변환 중앙값 | 722.5 ms | 769.9 ms | 별도 관찰 |
| 색인 중앙값 | 233.7 ms | 247.1 ms | 500 ms |
| 조회 p95 | 24.8 ms | 28.7 ms | 75 ms |
| 색인 디렉터리 | 120 KiB | 128 KiB | 256 KiB |

19문항의 응답 배열은 전후 5회 모두 동일했다. Excel 행 F1은 85.71, 두 문서 대조는 100, PPT 직접 연결 장표는 40, 텍스트·그림은 각각 100이다. 이 단계에서는 형식별 관계 추출이나 검색 순위를 바꾸지 않았다.

### 관계 저장 경로

기준선 원본 7개에 가상 관계를 50개씩 게시했다. 350개 저장 중앙값은 97.5 ms, 색인 증가량은 16 KiB였다. 매 실행에서 문서당 10회씩 읽어 원본 지문과 전체 50개 관계를 확인했다. 5회 실행별 조회 p95의 중앙값은 7.0 ms였다. 이 측정은 저장·조회 비용을 다루며 업무 관계의 추출 정확도는 형식별 단계에서 평가한다.

기존 기준선 스크립트로 만든 출력 폴더를 사용해 아래 명령을 저장소 루트에서 실행한다. 마지막 인수는 아직 존재하지 않는 폴더여야 한다.

~~~powershell
$run = '<기준선 실행 폴더>'
& "$env:JAVA_HOME/bin/javac" -encoding UTF-8 -cp 'target/classes;target/app/*' -d $run qa/wiki-baseline/EvidenceCost.java
& "$env:JAVA_HOME/bin/java" -cp "$run;target/classes;target/app/*" EvidenceCost "$run/sources" "$run/evidence-1"
~~~

### 원본 크기 영향

희소 Excel 원본의 시트 XML에 32 MiB의 무압축 주석을 추가해 셀 값과 19문항 정답을 그대로 유지했다. 해당 원본 크기는 33,572,176바이트였다. 버전별 3회에서 전체 7개 변환 중앙값은 840.6 ms에서 1,184.8 ms로 증가했고, 조회 p95는 28.2 ms에서 27.9 ms였다. 임시 복사와 원본 바이트 검증 비용이 있어 큰 원본의 변환 시간을 별도로 추적해야 한다. 이 시험은 다수 파일을 포함한 운영 보관함의 동시 처리량을 측정하지 않는다.
