# #9 제품 경로의 선택형 장표 검색 B

기본 출시는 보류 상태다. OfficeSearch에서 실험용 색인을 준비하면 기존 제품 검색창과 CLI의 관련도 검색 경로에서 B를 시험할 수 있다. 색인 준비는 등록한 PPTX의 장표 본문을 한 번 읽는다. 작성자의 기본 보관함과 구분되는 시험용 보관함을 사용한다.

~~~powershell
OfficeSearch.exe --prepare-slide-search
OfficeSearch.exe --experimental-slides "스케줄표를 보여주는 장표 찾아줘"
~~~

Java로 직접 실행할 때는 두 명령 모두 같은 `-Dofficemd.dataDir`를 지정한다. 검색창 실험은 해당 JVM에 `-Dofficemd.experimentalSlideSearch=true`를 설정하고 전체·관련도순으로 조회한다. 일반 실행에서는 실험 경로가 꺼져 있다. 기존 색인이 준비되지 않은 검색창은 기존 검색으로 처리한다.

## 동작과 검증 범위

* 제품 SQLite에 원본 노트·장표별 본문과 첫 텍스트 행을 저장하고 FTS5 검색에 사용한다. 원본 표시 번호를 보존하며 같은 원본·장에 중복으로 적재된 노트는 결과를 하나만 표시한다. 보류된 노트는 기존 가시성 조건을 따른다. 설치 후 신규 변환, 개정, 삭제, 구형 색인 가져오기는 해당 문서의 쓰기 트랜잭션에서 반영된다.
* B는 요청 표현과 일부 조사를 정리하고 일정·스케줄 등 제한된 어휘 변형을 묶는다. 핵심 어휘 묶음이 같은 장에 모두 있어야 후보로 남긴다. 없으면 기존 검색창의 빈 결과를 사용한다. 검색어가 다른 장에 흩어진 경우를 걸러내지만, 이미지 속 단어나 검색어와 다른 표현만 사용한 적합 장표도 놓칠 수 있다. 추가 OCR이나 그래프는 이번 변경 범위 밖이다.
* 과거 동결 51장과 판정표는 새 개발·측정에 사용하지 않았다. 개발군 9개 PPTX 134장을 제품 변환기로 새로 색인했다. 원래 8과제 외에 일정 표현 변형 1건과 부재 진단 6건을 분리했다. 후자 중 4건은 특정 어휘가 없고, 2건은 두 어휘가 각각 다른 장에만 나타난다. 이 조건은 어휘 수준의 부재 진단이다.
* D3의 개발 원본에는 ‘수행 일정’과 월 단위 일정표가 있다. 기존 Python B에서 ‘스케줄표를 보여주는 장표 찾아줘’는 후보 0개였다. 새 B에서 이 장표는 2위, 원래 ‘추진 일정’ 과제에서도 2위였다. 이는 일정 표현 차이로 발생하는 누락을 개발군에서 재현한 결과다. 미사용 시험의 T07 개별 원인은 재검사하지 않았다.

## 개발 정확도

| 지표 | 일반 검색 A | 이전 실험용 B | 새 제품 B |
|---|---:|---:|---:|
| 기존 8과제 지정 장표 후보 포함 | 1/8 | 8/8 | 5/8 |
| 기존 8과제 상위 3개 적중 | 1/8 | 2/8 | 4/8 |
| 추가 부재 진단에서 비어 있지 않은 결과 | 0/6 | 6/6 | 0/6 |

새 B의 D1~D8 첫 지정 장표 순위는 2·누락·2·1·2·4·누락·누락이었다. 이전 B와 비교해 서버 연결·신입사원 권한·대리 계정 신청 과제에서 지정 장표가 빠졌다. 부재 진단의 개선과 이 누락을 함께 새 독립 평가에 넘긴다.

## 엔진 지연과 색인 비용

Windows, i9-12900K, JDK 21, 최대 힙 2GiB, 결과 상한 500, 동일 JVM에서 순서를 교대했다. 아래 p95는 준비 실행을 제외한 nearest-rank 값이다. 개발 15과제는 방식별 300회, 5만 합성 문서 4과제는 방식별 80회다. 합성 색인은 100만 본문·제목 행, 95만 장표이며 문서마다 제목 행 하나와 한 줄짜리 장표 19개가 있다. 실제 문서의 긴 본문·이미지 분포와 다르다.

| 조건 | A p95 (ms) | B p95 (ms) | B/A |
|---|---:|---:|---:|
| 개발 15과제 전체 | 9.16 | 7.50 | 81.9% |
| 개발 D4 연동 신청 | 6.92 | 8.51 | 123.0% |
| 합성 4과제 전체 | 2,887.24 | 810.10 | 28.1% |
| 합성 일정 요청 | 484.79 | 16.42 | 3.4% |
| 합성 선택어 요청 | 322.91 | 17.37 | 5.4% |
| 합성 밀집 요청 | 2,894.77 | 817.88 | 28.3% |
| 합성 부재 요청 | 425.24 | 2.09 | 0.5% |

개발 전체 p50은 A 6.50ms·B 5.13ms, 합성 전체 p50은 A 432.09ms·B 15.93ms였다. 전체 p95는 두 조건 모두 기존 허용비 120% 이내였다. 과제별로는 개발 14/15건과 합성 4/4건이 허용비 이내였다. 개발 D4는 A 대비 1.59ms, 23.0% 느렸다. 응답 시간은 실제 제품 검색 호출을 재며 화면·미리보기 및 사용자의 판단 시간은 제외했다.

기존 색인에 장표 색인을 추가하는 데 개발군 23.71ms·249,856바이트, 5만 합성군 49.01초·407,703,552바이트가 추가됐다. 후자의 파일 크기는 약 348.1MiB에서 736.9MiB로 증가했다. 정답·지연·디스크 비용은 별도로 판정한다.

## 새 독립 평가 자료

현재 DOC 메타데이터 감사표에서 잠금 2개·암호화 64개와 이미 판정한 3개를 제외하면 17개다. 6개는 이전 작업 또는 최근 파일 기록이 있고, 10개는 사용한 파일과 장표 부품 CRC·크기가 겹친다. 나머지 1개(53장)는 사용한 같은 프로젝트의 동일 번호 운영 매뉴얼 계열로 계보가 불확실하다. 독립성이 확인된 새 묶음은 확보하지 못했다.

다른 프로젝트의 미사용 PPTX 원본 또는 오너가 정상적으로 열 수 있도록 제공한 암호화 문서의 승인된 사본이 필요하다. 기존 자료의 사본·개정본·공유 장표를 구별할 수 있도록 원본 경로, 버전·계보 및 이전 열람 여부를 먼저 확인한다. 약 60장에 여러 실제 작성 과제를 배정하고, 일정·흐름·그림 위주·연결선 없음·무관한 동명과 부재 사례를 포함할 수 있는 구성을 요청한다. 문서와 질문을 먼저 동결하고 독립 판정 후 같은 후보 범위에서 비교한다. 오너 결정에 따라 사람 검토는 상위 결과를 질문·파일·장 번호별로 합쳐 방식을 가리고 ‘맞다/아니다’만 기록한다. 실제 선택 시간과 조작 횟수는 측정하지 않는다.

## 재현

Maven package 후 JDK 21로 아래 벤치마크를 컴파일한다. JSON 설정의 docs는 개발 원본의 alias/path 목록, tasks는 id/query/gold 목록이며 gold는 alias/number 쌍이다. 각 원본을 새 시험 색인으로 변환하고 동일 프로세스의 SearchIndex.searchCached에서 A/B 실행 순서를 번갈아 1회 준비·20회 측정한다. 각 과제·방식의 전체 결과 필드와 순서가 반복 간 달라지면 실패한다. 합성 자료는 docs가 빈 설정과 별도의 합성 색인 사본을 사용한다.

~~~powershell
$cp = 'target/classes;target/app/*'
& "$env:JAVA_HOME/bin/javac" -encoding UTF-8 -cp $cp -d target/test-classes qa/slide-search/ProductSlideBenchmark.java
& "$env:JAVA_HOME/bin/java" -Xmx2g "-Dofficemd.dataDir=$trialDir" -cp "target/test-classes;$cp" ProductSlideBenchmark $config $results 20
~~~
