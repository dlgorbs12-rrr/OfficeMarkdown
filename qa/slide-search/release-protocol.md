# 참고자료 검색 설계와 출시 평가 v2

## 사용자가 끝내려는 일

착수보고서를 작성하는 사람이 “시스템 구성도 잘된 거 찾아줘”라고 입력하면, 참고할 만한 장표를 미리 보고 하나를 골라 원본의 해당 페이지를 연다. 문서명·요구사항 ID를 알거나 프로젝트·파일 쌍·위키 모드를 고르는 단계는 필요하지 않다. “잘된”의 의미는 사용 목적에 따라 달라진다. “전체 배치”, “서버 이중화”, “외부 연계”처럼 원본에서 확인한 차이를 결과에 표시하고 선택은 작성자에게 둔다.

검색 단위는 열 수 있는 원본 위치다. PPT는 한 장, Excel은 시트의 표·행, Word·PDF는 절·페이지다. 첫 출시 판정은 PPT에 한정한다. 다른 형식의 정확한 셀·인용 찾기는 기존 회귀 과제로 유지하며 PPT 점수와 합산하지 않는다.

## 자료에서 결과까지

| 단계 | 제안하는 처리 | 확인할 실패 |
|---|---|---|
| 색인 | 원본 버전·위치에 페이지 제목, 실제 본문, 그룹 도형 라벨, OCR과 미리보기 위치를 연결한다. 필드별 추출 여부를 남긴다. | 그림 안에만 정답이 있거나 읽기 실패한 경우를 실제 부재로 표시하는지 |
| 위키 작성 | 색인 시점에 주제·별칭·다루는 업무와 짧은 설명 후보를 만든다. 각 진술에 원본 위치와 버전을 붙인다. 명시적 연결선, 사람이 승인한 개체 대응, 모델이 제안한 관련 개념을 구분한다. | 같은 파일명이나 비슷한 라벨만으로 다른 프로젝트의 개체를 합치는지 |
| 질의 해석 | 사용 중인 화면이 제공하는 작업 맥락과 질문에서 주제·원하는 산출물·필수 조건·선호를 구분한다. “구성도”는 주제이고 “한눈에”는 순위 선호다. 명시한 제외 조건은 보존한다. | “찾아줘”가 없거나 “그림이 필요해”라고 했을 때 장표 후보 검색을 건너뛰는지 |
| 후보 생성 | 기존 검색 결과를 유지하면서 제목·본문·OCR의 장표 단위 검색과 출처 있는 주제·별칭 검색을 비교한다. 구조적 간선 또는 위키 주제를 통해 기존 후보에 없던 장표도 찾는 경로를 실험한다. 후보를 원본 버전·페이지로 중복 제거한다. | 필수어 AND 때문에 한 장이 탈락했는지, 각 경로의 상한이나 통합 순서에서 사라졌는지 |
| 근거와 순위 | 제목의 직접 일치, 같은 장의 근거, 주제 일치, 확인된 연결을 따로 기록한다. 그래프 확장은 첫 실험에서 가시 범위 내 1단계로 제한한다. 양 끝의 버전·가시성을 검사한다. | 연결선 수만 많은 장표가 오르거나 연결선 없는 좋은 장표가 빠지는지 |
| 결과 선택 | 기존 검색창에서 미리보기·제목·페이지·추천 근거를 보여준다. 약한 참고 후보와 명시 조건을 충족한 추천을 구분한다. 원본을 열 수 없으면 상태를 표시한다. 그래프 지연·실패 때는 기존 결과를 먼저 제공한다. | 불필요한 질문, 지연된 재정렬로 인한 선택 이동, 잘못된 페이지 열기 |

첫 구현은 출처 있는 어휘·구조 색인만으로 측정한다. 임베딩이나 LLM 요약은 각각 하나의 추가 실험으로 끄고 켜서 비교할 수 있다. 문서 수정·삭제·권한 변경 때 영향받은 페이지·위키 진술·간선을 다시 계산하고, 이전 버전 근거는 현재 추천에서 제외한다. 모델 호출량·색인 시간·디스크와 증분 갱신 비용도 함께 기록한다.

## 어떤 방식을 비교하는가

동일한 문서 버전·세션 가시성·질문·후보 상한·반환 형식에서 A는 현행 일반 검색, B는 그래프 없는 장표 검색, C는 **동일한 B 후보**에 그래프 근거로 순위만 조정한 검색이다. G는 B에 위키·그래프 경로의 새 후보를 합친 검색이다. G는 제안 단계이며 기존 실험 도구는 A/B/C만 실행한다. G를 구현하면 경로별 후보, 중복 제거 전후 순서, 제한 도달·시간 초과 여부를 남기고 동일한 보고서 형식에 G를 추가한다.

B−A는 장표 검색의 가치, C−B는 재정렬의 가치다. G−B는 확장 포함 전체 이득이며, G에서 B 전체 후보에 없던 정답이 새로 상위 20개에 들어온 과제 수도 센다. 재정렬과 확장의 단독 기여를 구할 때에는 같은 점수 함수로 확장만 끈 대조군도 실행한다. 후보 생성이 비어 있으면 C의 순위 기여는 측정 불가로 남긴다. 한 질의 유형에서만 효과가 있으면 해당 유형의 제한 출시로 별도 판정한다.

## 평가 자료와 채점

1. 실제 작성자에게 파일 제목을 보여주기 전에 요청을 수집한다. 구성도, 연동·절차, 일정, 화면 예시를 포함한다. 그림 위주·연결선 없는 장표·동명 오답·명시적 제외·자료 없음 사례를 확보한다. 개발·조정에 본 파일, 복사본, 개정본은 같은 계보로 묶고 미사용 평가에서 제외한다.
2. 시험 전에 질문, 파일 해시·계보, 버전·가시성, 질문 유형, 비교 방식과 임계값을 동결한다. 두 판정자가 원본을 보고 각 과제의 복수 적합 장표를 표시한다. 직접 재사용 가능·약한 참고·부적합·판독 불가를 구분하고, 불일치를 조정한다. 주 점수는 직접 재사용 가능한 장표 기준이며 약한 참고를 포함한 민감도도 별도로 보고한다. 읽지 못한 범위를 부재 분모에 넣지 않는다. 약한 참고만 있는 과제는 신규 주 평가 봉투에서 제외하고 민감도 분모에 포함한다. 과거 67장 재채점에는 당시 동결된 이진 판정을 그대로 사용한다. 봇 판정은 진단에 쓰며 실제 선택은 작성자가 수행한다.
3. 이번 프로토콜의 최소 운영 표본은 적합 과제 40개, 전수 판독한 부재 과제 20개, 서로 다른 문서 계보 4개다. 임의 기본값으로 정한 파일럿 기준이며 통계적 충분성을 보장하지 않는다. 질문 유형·파일 계보별 분모와 승패를 함께 제시하고, 특정 계보가 결론을 뒤집으면 독립 자료를 보강한다. 이전의 2파일·67장 시험은 회귀 진단에만 재사용한다.

| 판정 축 | 적용 기준 |
|---|---|
| 후보와 순위 | 적합 과제 중 상위 20개에 적합 장표가 하나라도 있는 비율 ≥80%. 상위 3개 적중의 **과제별 순증**은 B 대 A, C 또는 G 대 B에서 각각 ≥20%p. v2 파일럿에서는 절대 상위 3개 적중도 ≥60%이며 모든 출시 후보가 운영 A의 상위 3개 적중 이상이어야 한다. B가 A보다 낮을 때 C/G가 B만 이기는 경우의 출시를 차단한다. 기존 오너의 상대 개선폭을 유지한다. 새로 성공한 질문과 잃은 질문을 함께 기록한다. |
| 부재와 근거 | 기존 자동 평가의 부재 과제에는 확정 추천 0건. 현행 출력은 모든 페이지를 추천으로 센다. 향후 약한 참고 후보 UI가 생기면 별도 출력으로 평가한다. 잘못된 원본·버전·페이지 인용, 범위 밖 노출은 1건이라도 출시 실패다. |
| 사용자 수고 | 적합 장표가 있는 선택 과제에서 실제 작성자 최소 4명이 유형·난이도를 맞춘 서로 다른 과제를 교차 수행한다. 최소 1인당 방식별 3회, 첫 질문부터 선택·포기까지 기록한다. 성공률 ≥A, 전체 과제의 선택·포기 시간 중앙값 및 클릭·재검색·추가 입력 평균 ≤A. 실패·포기를 포함하고 즉시 포기로 시간이 줄면 성공률과 함께 판정한다. 한 참여자나 유형에 악화가 집중되면 확대 전 재시험한다. |
| 속도와 규모 | 기존 p95 ≤A의 120% 기준을 유지한다. 엔진뿐 아니라 첫 미리보기 표시도 측정한다. 5만 문서에서 적중·부재·밀집 질의, 차가운 첫 조회와 준비 후 반복 조회, 동시 검색·증분 색인 중 검색을 분리한다. 각 반복 셀은 질의별 준비 1회와 본측정 ≥20회, 시간 초과·오류를 포함해 보고한다. 운영 대상의 절대 지연 예산도 후보 결과를 열기 전에 기록한다. 빈 응답만 빠른 셀로 적중 셀을 대체하지 않는다. |
| 기존 사용자 회귀 | 일반 문서명·정확 ID·셀/인용·그림 검색에서 기존 고정 과제의 상위 적중 하락 0건, 필터와 원본 열기 일치, 잘못된 장표 모드 강제 0건을 확인한다. 이전 색인과 그래프 비활성·오류·시간 초과에서 일반 검색 성공 및 추가 필수 입력 0건을 확인한다. [기존 회귀 하네스](../wiki-baseline/README.md)를 함께 실행한다. |
| 출시 결정 | 품질과 사용자 수고, 성능, 출처·가시성 검사를 모두 통과한 방식만 기본 적용한다. 실패는 원인·해당 방식과 함께 보류, 증거 부족은 미판정이다. B 출시와 C/G 기본 적용은 독립 기록한다. 상위 3개가 그대로인 경우라도 선택 시간이 개선되면 별도 UX 실험으로 기록하고 순위 게이트 결과는 유지한다. |

## 실행과 판정 기록

신규 봉투는 기존 documents.tsv에 version과 revision_family를 채우고, 두 판정자의 조정 결과를 owner/judgments.tsv 열 구조로 판정표.tsv에 저장한다. 모든 질문×파일×페이지에 한 행을 두며 suitable은 yes(직접 적합), weak, no, unreadable 중 하나다. 한 페이지라도 판독 불가한 과제는 주 분석과 민감도에서 제외한다. 예전 집계형 판정표는 과거 결과 재현용이다. 신규 생성기는 정답을 검색에 입력하지 않고, 순위와 시간 표본을 먼저 저장한 뒤 동결 입력 3종의 해시를 담은 report.json을 v2 채점기에 넘긴다. holdout.py는 두 판정표 형식을 지원한다. 현재 제품 A/B/C는 기존 절차와 같이 holdout.py <동결-입력-폴더> <새-출력-폴더> <Java-classpath> --product-b로 실행한다.

기존 동결 봉투와 제품 실행의 원시 순위·시간 표본을 사용한다. 다음 명령은 입력 해시를 대조하고 누락된 방식·중복 페이지·범위 밖 번호를 거절한다. 원본 내용과 질의문은 출력하지 않는다.

~~~powershell
py -3 -X utf8 qa/slide-search/release_quality.py <동결-입력-폴더> <제품-평가-report.json>
~~~

실사용 기록은 기존 trials.tsv 열로 수집해 같은 명령에 `--trials <trial.tsv>`를 붙인다. 한 작성자에게 같은 과제를 반복하지 않는다. success는 1/0으로 쓰고 포기하면 선택 위치를 비우고 소요 시간과 조작 횟수를 남긴다. 비교하는 방식끼리 동일 참여자와 참여자별 동일 횟수를 요구한다. 과제 난이도·순서 균형 및 참여자별 악화는 별도 검토한다.

출력의 quality는 자동 품질 부분 판정이다. engine_latency는 해당 입력 규모의 엔진 지연 판정이다. 계보 독립성, 근거의 정확성, 미리보기·권한, 5만 건 부하와 사용자 수고는 원본 검토 및 기존 trials.tsv로 따로 확인한다. 자동 점수만으로 출시하지 않는다. #9에는 방식·대조군·입력 해시, 과제별 승패, 규모별 지연·실패, 실제 선택 결과, 미검증 항목, 출시 범위를 남긴다.

67장 보고서 재채점에서 적합 3개·부재 9개, A/B/C 상위 20개와 상위 3개 모두 0/3, 부재 추천 0/9였다. 엔진 p95는 7.6340 / 7.6376 / 7.4432ms였다. B/C 자동 품질은 표본 부족이고 관측 개선폭도 0%p다. G 실행과 사용자 선택 기록은 없다. 재채점은 기존 보류를 유지하며 새로운 독립 평가 실적으로 세지 않는다.

동일한 두 원본을 제품 A/B/C로 다시 변환·색인해 12문항을 실행한 결과도 세 방식 모두 후보 0건이었다. 이 재실행에서 엔진 p95는 A 10.8415, B 10.2411, C 10.2401ms였다. 동일한 질문을 반복했으므로 독립 표본 수는 늘지 않는다.
