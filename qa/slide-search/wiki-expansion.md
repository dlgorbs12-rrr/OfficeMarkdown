# 위키·그래프 후보 확장 첫 실측

착수보고서에 넣을 참고 장표를 일상적인 표현으로 찾는 사용자가 첫 결과에서 적합한 원본 페이지를 얻는지 측정했다. 첫 구현은 별도 평가 옵션이다. 기본 검색 적용은 보류한다.

## 색인과 검색

동결된 PPTX를 제품 변환기로 색인한 뒤 읽을 수 있는 파일과 장 번호를 대조한다. 장표 본문과 명시적 제목에서 단어별 역색인을 만들고, 원본 PPTX 연결선 양끝의 텍스트를 같은 파일의 페이지에 연결한다. 현재는 원본에 있는 단어와 명시적 연결선을 사용한다. 그림 픽셀과 업무 개념의 동의어는 입력에 포함되지 않는다.

기존 장표 검색 B의 순서를 보존하고 남은 자리만 채운다(최대 500장). T는 제목 한 단어 또는 본문 두 단어가 맞는 후보를 추가한다. E는 T에 연결선 끝점 어휘가 맞는 출발 장표를 더한다. G는 E에서 한 번 더, 반대쪽 라벨 전체가 제목·목록·본문 한 줄과 일치하는 같은 파일의 장표까지 찾는다. G와 E의 차이로 연결을 따라 발견한 효과를 확인한다. 같은 페이지는 한 번 반환한다. 근거는 동결 원본 식별자와 장 번호, 연결선 순번·방향, 일치 단어로 추적한다. T/E 대조군 실행은 G 응답 시간에서 제외한다.

## 자연어 과제 12개

서로 다른 실물 PPTX 두 파일 총 67장을 기존 동결 판정표로 재측정했다. 적합 과제는 3개, 부재 과제는 9개다. 과제별 준비 1회와 본측정 20회를 수행했다.

| 방식 | 적합 과제 Top 3 / Top 20 | 부재인데 결과를 낸 과제 | 엔진 p95 |
|---|---|---|---:|
| 일반 검색 A | 0/3 · 0/3 | 0/9 | 8.05 ms |
| 장표 검색 B | 0/3 · 0/3 | 0/9 | 7.75 ms |
| B 후보 재정렬 C | 0/3 · 0/3 | 0/9 | 7.89 ms |
| 후보 확장 G | 0/3 · 0/3 | 4/9 | 7.99 ms |

G가 추가한 질문·페이지 쌍은 18개였다. 모두 T에서도 나왔고, 연결을 따라 새로 찾은 적합 장표는 0개였다. 정답이 있는 Q01·Q03은 후보가 없었고 Q09는 부적합 장표 1장을 반환했다. 질문과 정답 페이지 본문의 정규화된 단어 교집합은 Q01·Q03에서 0개, Q09에서 페이지당 1개였다. 같은 판정표를 재사용했고 실제 작성자의 선택 시험은 수행하지 않았다.

## 규모별 비용

합성 문서당 장표 5장과 연결선 1개로 색인을 구성했다. 질의별 준비 후 20회 단일 사용자 반복한 확장 단계 p95다. B·파일 변환·XML 해석·미리보기·동시 색인은 측정 구간 밖이다.

| 합성 문서 / 장표 | 메모리 색인 구성 | 흔한 표현 | 선택적 연결선 | 검색어 부재 |
|---|---:|---:|---:|---:|
| 5천 / 2.5만 | 0.20 s | 13.19 ms | 0.133 ms | 0.003 ms |
| 5만 / 25만 | 2.03 s | 235.85 ms | 1.81 ms | 0.0035 ms |

5만 문서에서 흔한 표현과 선택적 연결선 모두 상한 500장, 부재 질의는 0장을 반환했다. 흔한 표현에서는 반환 상한을 적용하기 전에 일치 페이지 전체를 채점·정렬한다. 이 수치는 실제 문서 5만 건의 품질이나 전체 응답 시간으로 환산할 수 없다.

## 재현과 다음 판정

기존 [실험 준비 절차](holdout-results.md)로 Java 하네스를 컴파일한 뒤 새 출력 폴더를 사용한다.

~~~powershell
py -3 -X utf8 qa/slide-search/holdout.py <동결입력> <새출력> <Java-classpath> --product-b --wiki
py -3 -X utf8 qa/slide-search/release_quality.py <동결입력> <새출력>/report.json
py -3 -X utf8 qa/slide-search/wiki_scale.py --documents 50000
~~~

다음 실험은 실패한 적합 장표 원본에서 개념을 식별할 수 있는 단서가 제목·그림 설명·도형 텍스트·이미지 중 어디에 있는지 확인하는 것으로 시작한다. 출처가 확인되는 단서를 개발 자료에서 색인한 뒤 독립 표본으로 재평가한다. [출시 기준](release-protocol.md)에 따라 실제 작성자의 선택 시간·재검색 횟수와 제품 경로의 5만 문서 성능도 확인해야 한다.
