# #9 동결 문서 A·B·C 최초 비교

오너가 확정한 12개 질문, 3개 원본 51장으로 측정했다. 출처·질문·판정표는 비공개이며 원본과 판정표를 측정 전후 해시로 대조했다. 후보 상한은 모두 500이다. 과제를 변경하거나 이 자료로 B·C를 다시 조정하지 않았다.

## 판정 자료

오너 위임으로 독립 비인간 판정자(Claude)가 36행을 작성했다. 검색 결과를 보지 않았고 B·C 구현에 참여하지 않았다. PPTX의 장 순서·텍스트·표·연결선 끝점을 읽었고 H02의 화면 캡처 7장(4·5·12·13·15·16·28)은 PowerPoint 내보내기 그림을 확인했다. H01 아이콘과 H03 17·18장의 그림 자체는 미확인이다. 판정 전 사본에서 T12/H03 질문과 일부 메모가 달랐고 변경자는 미상이다. 판정자가 동결된 질문으로 복원했다. 채점 시 36행의 문구와 과제·파일 조합을 검증했다. 최종 판정표 SHA-256은 `49331baad8ebd33f8552d944e9bc54472ea4097c45bbad7d80a046a9d4f7ed08`이다. 오너의 실제 선택·사용성 시험은 별도로 남아 있다.

## 조건

* A는 격리한 제품 색인에서 원문을 SearchIndex.searchCached(ALL, RELEVANCE, 500)에 보내고 장표만 선별했다. 같은 제품 변환기로 원본 3개를 변환했으며 추가 OCR 서비스는 사용하지 않았다.
* B는 PR #15의 질의 정규화와 장표 텍스트 관련도 점수를 그대로 사용했다. C는 같은 B 후보를 기존 #5 탐색 규칙으로 재정렬했다. 연결선 양끝의 비어 있지 않은 도형 라벨에 질의어가 각각 대응하고 합쳐서 서로 다른 두 단어 이상이면 우선한다. 동점에서는 B 순서를 유지했다. 원본 관계는 메모리에 한 번 적재했다. 화살촉 또는 업무 의미는 이 실험에서 평가하지 않았다.
* 과제당 1회 준비 후 각 방식 20회, 세 방식의 실행 순서를 순환했다. 매번 같은 순위였고 오류·시간 초과는 없었다. A는 JVM 안에서 실제 조회·장표 선별, B·C는 Python에서 SQLite 본문 조회·점수 계산까지 측정했다. 언어·실행 경로 차이를 포함한 실험 엔진 지연이며 네트워크, 화면 미리보기, 사용자 선택 시간은 포함하지 않는다.

* 적합 장표가 있는 7과제에서 A/B/C의 상위 1개 적중은 0/2/4건, 상위 3개 적중은 0/6/6건이다. 23개 과제·적합 장표 조합 중 후보에 든 조합은 각각 0/20/20건이다. B−A는 +85.7%p, C−B는 0%p다.
* 양끝에 라벨이 있는 연결선은 12장에 104개였다. T04 한 후보, T06 세 후보에서 우선 조건이 맞았고 네 후보는 판정표상 모두 적합했다. T07의 적합 장표는 B 후보에서 빠져 C도 복구할 수 없었다. 부재 5과제에 B·C가 모두 8~44개 후보를 반환해 상위 3개가 각각 15/15 비적합이었다. 부재 과제에 그래프 승격은 없었다.
* 방식별 준비 실행을 제외한 240회 전체 p95는 A 3.34ms, B 8.71ms, C 8.57ms였다. 허용치 A×1.2는 4.01ms다. 그래프 사전 적재는 98.66ms(1회)였다. 운영 규모의 p95, 첫 화면, 실제 선택 시간은 아직 확인되지 않았다.
* 오너 기준에 따라 그래프 기본 적용을 보류한다. B는 적중 개선폭을 달성했으나 지연 기준을 넘었고 부재 과제 오탐이 남았다. 미사용 자료를 추가 튜닝에 사용하지 않고 후속 진행 여부를 오너에게 묻는다.
