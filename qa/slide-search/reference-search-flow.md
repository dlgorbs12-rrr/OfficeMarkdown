# 참고 장표 검색 흐름과 제품 적용 검토

## 결정

PPTX 참고자료 요청의 다음 제품 시험은 **동일 비중으로 통합한 상위 4장을 텍스트로 한 번에 판독하고, 근거가 있는 장표를 최대 3장 표시**한다. Codex의 기준 판독기는 GPT‑6.1 Terra medium이다. 기본 적용은 독립 자료·작성자·제품 부하 시험 뒤에 판정한다.

## 자료가 들어올 때

1. 제품 시험에서는 변환·색인 과정에서 원본 버전, 실제 표시 순서의 장 번호, 제목·본문·도형 라벨·추출된 OCR을 장표 단위로 연결한다. 파일명만 같은 문서는 별도로 취급한다.
2. 원본 장표를 렌더링해 실제로 보이는 주제·구조·동작과 짧은 라벨을 설명으로 저장한다. 원본 장표, 입력 버전, 생성 모델·프롬프트 버전, 준비·실패 상태를 기록한다. 설명은 후보 검색에 사용하고 최종 근거는 원본에서 확인한다. 파일 교체·삭제·권한 변경 때 기존 설명과 미리보기의 조회 가능 여부도 갱신한다.
3. 사용자가 검색할 때마다 설명을 만들면 첫 결과가 늦어진다. 백그라운드에서 준비된 설명만 검색에 사용하고, 준비 중이거나 실패한 장표는 현재 버전의 본문으로 검색한다. 67장 설명 생성에는 입력 418,297·출력 5,466토큰이 들었다. 대규모 일괄 생성 전에 별도로 생성 비용과 변경 장표 재처리량을 측정한다. 설명 생성 모델은 선정이 필요하다.

## 질문이 들어올 때

~~~mermaid
flowchart TD
    Q["기존 검색창에서 한 번 질문"] --> I{"참고 장표 요청인가?"}
    I -->|일반 문서·ID·셀 등| A["기존 검색 결과"]
    I -->|참고 장표| C["필수·제외 조건과 검색어 추출"]
    C --> B["장표 본문 상위 20장"]
    C --> W["원본에 연결된 장표 설명 상위 20장"]
    B --> F["페이지 중복 제거 및 순위 통합"]
    W --> F
    F -->|후보 있음| J["상위 4장을 한 번에 텍스트 판독"]
    F -->|후보 없음| N["현재 범위의 검색 결과 안내"]
    J -->|직접 적합| R["근거와 페이지를 붙여 최대 3장 추천"]
    J -->|적합 장표 없음| N
    J -->|판독 실패·시간 초과| L["일반 검색 결과 이용 가능"]
~~~

- “착수보고서에 쓸 시스템 구성도 잘된 거 찾아줘”에서 사용 목적은 착수보고서, 대상은 시스템 구성도다. “잘된”은 사용자 선호로 두고 각 장표에서 확인된 구성요소·계층·연결 차이를 설명한다. 파일명·ID·프로젝트·검색 모드를 추가 입력으로 요구하지 않는다. 현재 SlideSearch.requested는 일부 명령어와 장표 명칭에 의존한다. “전체 서비스가 어떻게 연결되는지 한 장이 필요해” 같은 요청과 정확한 셀 조회를 함께 회귀 시험한다. “로그인 화면은 제외” 같은 조건은 동의어 확장 후에도 원문 그대로 판독기에 전달한다.
- 두 경로는 동일한 세션의 허용 문서·구역과 현재 버전을 먼저 적용한다. 원본 식별자·버전·장 번호로 동일 장표를 합치고, 경로별 1위부터 **1/(10+순위)** 를 더한다. 동점은 안정적인 페이지 키 순서로 정한다. 본문 순위를 고정하지 않는다. 기존 실험에서 명시적 연결선으로 추가 회수한 적합 장표는 0장이었다. 그래프 확장은 별도 실험 경로로 둔다.
- 후보 1~4장의 질문·원본 텍스트·세션 내 페이지 핸들을 한 번에 전달한다. 출력은 페이지별 적합·부적합·판독 불가, 순서, 짧은 근거다. 서버가 핸들·버전·범위·인용을 확인한 결과만 추천한다. 추천 직전과 원본 열기 때도 유효성을 확인한다. Claude·Copilot 사용자의 제공자 설정은 존중하고 해당 조합의 제품 품질을 별도로 검증한다.
- 시각 질문에서도 **검색 시 원본 이미지 재판독은 별도 옵션**이다. 그림 관계나 필터 조작이 판정에 결정적이고 텍스트로 확인할 수 없는 경우에만 시험한다. 판독 불가·권한 변경·색인 미완료를 실제 자료 부재로 표시하지 않는다.

## 화면에서 보이는 변화

현재 검색 결과는 먼저 이용할 수 있게 하고, 같은 화면에 비동기적으로 **추천 장표**를 표시하는 안이다. 카드에는 문서 제목·장 번호, 미리보기, 질문과 맞는 근거 한 줄, 원본 해당 장 열기를 둔다. 일반 결과와 검토 완료 추천을 구별하고, 이미 선택한 행이 뒤늦게 이동하지 않게 한다. 새 질문을 입력하거나 취소하면 이전 요청의 늦은 응답을 버린다. 원본 페이지 이동을 제공할 수 없는 환경에서는 정확한 장 번호와 페이지 미리보기를 제공하고 버튼은 실제 동작에 맞춰 ‘파일 열기’로 표시한다.

## 제품 적용 순서

| 순서 | 현재 코드와 필요한 변경 | 검수 기준 |
|---|---|---|
| 1. 공통 장표 조회 | SlideSearch와 SearchIndex의 페이지 색인·갱신을 재사용한다. 현재 실험 경로의 필수어 검색과 두 글자 부분 일치·동의어를 사용한 실측 본문 검색은 알고리즘이 다르다. 설명 저장소와 두 경로의 순위 통합을 공통 서비스로 구현한다. | 같은 동결 입력에서 경로별 상위 20개, 통합 상위 4개, 장 번호·버전·가시성 및 재색인 중 조회를 대조한다. |
| 2. 에이전트 연결 | OfficeIndexMcp의 search는 문서별 그룹으로 최대 12건을 반환한다. 페이지 후보와 근거를 읽는 세션 핸들을 추가하고 기존 도구 호환을 유지한다. 현재 대화 진입은 AgentDialog → McpSearch.chat이다. 별도 ask 경로에는 문서당 하나로 제한하는 처리도 있다. GUI와 MCP 모두 공통 조회를 사용하게 한다. | 같은 PPT의 적합 장표 2장을 독립 추천한다. 모델 1회에 최대 4장, 확정 추천 최대 3장, 범위 밖 페이지 0건을 검증한다. |
| 3. 화면·원본 열기 | OfficeMarkdown의 일반 검색과 AgentDialog의 근거 표시·열기 동작을 연결한다. 현재 파일 열기는 지원 파일을 데스크톱 앱에 넘긴다. 정확한 장 이동과 취소·시간 초과·늦은 응답을 제품에서 확인한다. | 기존 검색창 한 번 입력으로 미리보기와 선택이 가능하고, 선택·필터를 보존한다. AI 사용 불가 시 일반 결과를 계속 열 수 있다. |
| 4. 제한 시험 | 기본값이 꺼진 옵션에서 먼저 같은 질의를 현행·신규 경로로 비교한다. 사용자에게 보이지 않는 비교에서는 기존 검색을 그대로 제공하고 후보 누락·비용을 기록한다. 설명 생성, 검색어 확장, 최종 판독의 호출·캐시·입출력 토큰을 각각 분리한다. 이후 동의한 작성자의 과제에서 선택까지 측정한다. | 아래 출시 기준을 통과한 경로만 기본 적용한다. |

### 출시 채점기 변경

현재 release_quality.py는 하나의 순위 목록으로 Top 20·Top 3·부재 반환을 계산한다. 제한 시험 전에 질문별 통합 후보 20장, 판독 입력 최대 4장, 검증을 마친 최종 추천 최대 3장, 응답 상태를 별도 저장하도록 실행기와 채점기를 바꾼다. 후보 Top 20 적중은 적합 질문 중 후보에 정답이 있었던 비율, 추천 Top 3 적중은 같은 질문 중 최종 추천에 정답이 남은 비율로 계산한다. 부재 질문은 최종 추천이 나온 경우만 오추천으로 집계하고 기술 실패는 오류율에도 기록한다. 후보가 있었으나 전부 부적합으로 판정된 부재 질문과, 정답이 후보 5위여서 판독하지 못한 적합 질문을 회귀 사례로 둔다. 그래프 없는 장표 검색 B를 개선폭 대조군으로, 현행 일반 검색 A를 사용자 회귀 기준으로 둔다. 본문·설명 통합 전후와 판독 전후의 승패도 별도 기록한다.

## 판단 근거와 출시 조건

- PPTX 2개·67장의 기존 12과제 중 적합 과제는 3개였다. 통합 상위 3장에서는 첫 추천 2/3, 통합 상위 4장에서는 3/3이었다. 부재 9개는 두 방식 모두 오추천 0개였다. 별도 구성도 질문에서는 4장 판독으로 적합 2장을 추천했다. 4장 방식은 같은 자료에서 탐색적으로 선정했다.
- 네 장씩 고정한 13질문에서 Terra medium은 후보 안의 적합 5장을 모두 회수했고 오추천은 0장이었다. 당시 캐시 사용량을 반영한 API 환산은 약 0.074달러다. 이 결과는 **검색 뒤 텍스트 판독**에 해당한다. 사용자 결제액, 이미지 판독과 위키 생성 성능은 별도다.
- 합성 문서 5만 건·25만 장표에서 구성도 질의의 준비 후 로컬 후보 조회·순위 통합 p95는 31.44ms였다. 4장 텍스트 판독 중앙값은 기존 실험에서 약 6.76초였다. 서로 다른 측정 구간이다.
- [출시 평가 v2](release-protocol.md)를 적용한다. 독립 문서 계보 ≥4, 적합 질문 ≥40·부재 ≥20, Top 20 적중 ≥80%, Top 3 적중 ≥60% 및 지정 대조군 대비 ≥20%p 순증, 일반 검색 대비 회귀 0건을 확인한다. 부재 과제 확정 추천과 잘못된 출처·범위 노출은 0건이어야 한다.
- 작성자 ≥4명이 방식별로 각 3회 이상 수행해 선택 성공률·선택 시간·클릭·재검색·추가 입력을 비교한다. 5만 문서의 준비 전후·동시 검색·증분 색인에서 엔진과 첫 미리보기 p95를 각각 비교하고, AI 추천 완료 지연·토큰·오류도 기록한다. 제품 실측과 작성자 시험 전까지 제한 시험 대상으로 둔다.
