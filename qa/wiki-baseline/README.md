# 문서 관계 검색 기준선

가상 Office 원본 7개를 생성해 현재 제품의 변환·색인·검색 경로로 질문 19개를 실행한다. Atlas는 개발용 11문항, Birch는 평가용 8문항이다. Atlas의 개정 전후 파일은 같은 묶음에 둔다. 검색은 두 묶음을 함께 색인한 환경에서 실행한다. 두 묶음은 일부 구조를 공유하므로 별도 현장 자료로 일반화 성능을 추가 평가해야 한다.

이 디렉터리에서 생성하는 가상 문서의 내용, 그림과 정답 자료는 CC0-1.0으로 재배포할 수 있다. 외부 고객 문서와 계정, Office 설치, 모델 연결, OCR 서비스는 필요하지 않다.

## 재현

Windows PowerShell, JDK 21(JAVA_HOME), Maven 3.9, Python 3.13을 사용한다. 저장소 루트에서 아래를 실행한다. 매 실행마다 target 아래 새 폴더에 원본과 전용 SQLite 색인을 만든다.

~~~powershell
py -3 -m venv .venv-wiki
.\.venv-wiki\Scripts\python -m pip install openpyxl==3.1.5 python-pptx==1.0.2 Pillow==12.3.0
.\qa\wiki-baseline\run.ps1 -Python (Resolve-Path .\.venv-wiki\Scripts\python.exe).Path
~~~

Maven이 PATH에 없으면 -Maven으로 실행 파일을 지정한다. -Runs 기본값은 5다. 각 run 폴더의 predictions.json에 문항 ID별 결과 배열을, cost.json에 변환·색인 시간, SQLite 디렉터리 바이트 수와 문항별 조회 시간을 기록한다. 측정 파일·가상환경은 로컬에서 보관한다.

## 무엇을 채점하는가

| 과제 | 질문과 정답 단위 |
|---|---|
| 원본·좌표 | verify_sources.py가 생성된 XLSX와 PPTX의 XML을 열어 셀 값, 도형 그룹, 양 끝점·화살촉과 그림 설명을 확인한다. 이 단계는 생성 자료와 수기로 고정한 정답의 대조다. |
| Excel 행 | 지정 문서에서 요구사항 ID로 read_evidence의 마지막 페이지까지 읽고 반환된 화면 ID 집합을 비교한다. 같은 ID가 다른 프로젝트에도 있고, 빈 셀과 멀리 떨어진 A2·DP2가 있다. |
| 문서 간 대조 | 질문에 지정된 두 파일에서 같은 ID를 각각 조회하고 공통·왼쪽만·오른쪽만 기록된 대상의 집합을 비교한다. 문서 선택 정확도는 별도 과제다. |
| PPT 장표 | 두 도형 이름으로 관련도 검색을 수행한다. 직접 연결된 경우에만 그 장표가 정답이다. 1장은 한쪽만 붙은 선, 2장은 양 끝이 붙은 선과 화살촉을 가진다. 같은 장표에 있는 세 번째 도형은 미연결이다. |
| 텍스트·그림 | 가상 그림 설명을 키워드·그림 검색으로 찾는다. 각 정답 장표에는 그림이 하나 있다. 이미지 적중은 해당 그림이 있는 장표 단위로 측정한다. OCR 글자 인식률은 별도다. |

질문과 정답은 각각 questions.json, gold.json에 있다. 새 조회 방식을 비교할 때 같은 질문을 사용해 ID별 배열을 predictions.json으로 내보내고 아래처럼 실행한다. 구현에서 gold.json을 읽지 않는다.

~~~powershell
py -3 qa/wiki-baseline/score.py <predictions.json의_실제_경로>
~~~

완전 일치는 결과 집합 전체, 상위 3개 적중은 정답이 있는 질문에서 처음 세 후보 중 하나 이상이 맞는지 측정한다. 부재 오탐은 정답이 빈 질문에서 후보가 하나라도 나온 횟수다. F1은 과제별로 TP·FP·FN을 합산한다. 아래 분수는 각각 해당 지표의 분모를 사용한다.

## 현재 기준선

제품 3.0.1, Windows x64, i9-12900K, JDK 21.0.13에서 새 색인으로 5회 실행했다. 5회 모두 문항별 결과가 동일했다.

| 과제 | 완전 일치 | 상위 3개 적중 | 부재 오탐 | F1 |
|---|---:|---:|---:|---:|
| Excel 행 | 5/6 | 3/4 | 0/2 | 85.71 |
| 두 문서 대조 | 3/3 | 3/3 | 대상 없음 | 100 |
| PPT 직접 연결 장표 | 0/4 | 2/2 | 2/2 | 40 |
| 일반 텍스트 | 2/2 | 2/2 | 대상 없음 | 100 |
| 그림 | 4/4 | 2/2 | 0/2 | 100 |

Excel은 같은 행에서도 A열과 DP열이 다른 색인 줄로 나뉘어 1건을 놓쳤다. PPT 검색은 이름이 나온 두 장표를 함께 반환해 상위 3개에는 정답이 들어가지만 직접 연결 여부를 구별하지 못했다.

## 후속 단계에 적용할 예산

원본 7개 기준 5회 중앙값은 변환 738 ms, 색인 229 ms, 색인 디렉터리 116 KiB였다. 95개 조회의 p95는 27.1 ms 이내였다. 변환과 색인 시간은 분리하고 새 JVM을 매번 실행한다. 시간에는 JVM 시작·자료 생성이 포함되지 않는다.

이 자료와 동일 장비 등급에서 **색인 중앙값 500 ms, 조회 p95 75 ms, 색인 크기 256 KiB**를 초기 회귀 예산으로 정한다. 초과하면 같은 장비에서 기존·변경 버전을 연속 5회 비교해 원인과 비용을 검토한다. 가상 소규모 자료의 예산은 대형 보관함 출시 기준과 별도로 관리한다. 후속 비교 시 일반·그림 검색의 적중을 유지하고, 미연결 장표와 다른 프로젝트의 항목을 확정 관계로 반환하는 경우를 별도로 센다.
